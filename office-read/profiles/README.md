# profiles/ — 組織固有の定型ファイルに関する知識の置き場

office-read / office-edit は汎用ツールです。「この xlsx の B3 は対象年月で、D10 の数式は触るな」
といった**特定ファイル固有の知識**はここに 1 ファイル 1 種類で置きます。

エージェントは office ファイルを扱う前にこのフォルダを見て、ファイル名やシート構成が一致する
プロファイルがあればそれを読み、書かれた制約を守ります。一致しなければ何もしません。

## 追加のしかた

1. 雛形を自動生成する（構造は埋まり、意味だけ TODO で残る）:

   ```bash
   python scripts/office2md.py "path/to/売上報告_202610.xlsx" --profile --out profiles/sales-report.md
   ```

2. 生成されたファイルの `TODO` を埋める。全部埋めなくてよい。分かっている行だけ残し、
   分からない行は消す。嘘が書いてあるより空の方がまし。
3. ファイル名は英語の短い kebab-case（`sales-report.md`）。先頭の `# 見出し` と `## 識別` が
   マッチングに使われるので、識別の行は具体的に書く。

## 書く価値があること（優先順）

- 触ってはいけないセル・シート・スライド（数式、マスタ、非表示シート）
- 「〜して」と頼まれたときの定型手順（例: 先月分を作る = コピーして B3 更新、明細クリア）
- ヘッダ行とデータ開始行、追加時の書式ルール
- 社外に出す前に消すもの
- 過去に壊れた経験

## 書かなくていいこと

- office2md --outline で分かること（シート一覧、サイズ、見出し一覧）。毎回読めるので不要。
- 一度しか扱わないファイル。

## 配置の選択肢

- このフォルダ: スキルと一緒に配布される。組織内だけで配るスキルコピーに向く。
- プロジェクト側 `.office-profiles/`: リポジトリ単位で管理したいときはこちら。
  SKILL.md はどちらも探す。

`_template.md` は空の雛形です。`--profile` が使えないファイル形式のときはこれをコピーしてください。
